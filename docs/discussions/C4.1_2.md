`representation-artifacts`

- allowlisted logical formats only
- internal artifact resolution from persisted representation metadata
- artifact-root containment validation
- readable-file checks
- safe JSON parsing for `native-json`

## Content behavior

For `format=text`, the API reads ordered `document_segment.text_content` from PostgreSQL rather than reading `text.txt` from disk.

For `format=markdown`, the API reads retained `markdown.md` only where it actually exists.

For `format=native-json`, the API reads retained `native.json` and returns parsed JSON.

The client cannot request arbitrary artifact paths or filenames.

## Safety behavior

Implemented safety guarantees:

- SHA-256 shape validation for binary detail routes
- integer validation for representation IDs
- allowlisted representation formats only
- no filesystem path parameter
- artifact resolution must stay inside the expected processing/legacy artifact roots
- artifact failures do not leak absolute local paths
- processing-job error text is sanitized before returning through the consultation API
