## Prompt Questions Answered

### 1. Is Docling actually losing the important header information?

No, not in the strongest tested example.

For `6836...`, the important procedural header lines are preserved in Docling as `FURNITURE`.

### 2. Is Xberg actually losing it?

Not on the tested target strings.

The installed Xberg defaults do exclude headers/footers and strip repeating text, but on these three PDFs the tested strings were already present in current output.

### 3. Can the problem be solved by changing how we preserve/project existing extractor output?

Yes.

The evidence supports improving:

- Docling layer-aware projection
- Xberg filter configuration

before adding another extractor.

### 4. Would a literal text projection still provide independent value?

Yes.

`pdftotext -layout` remains valuable as a literal page-surface baseline and debugging tool.

### 5. Is `pdftotext -layout` justified as a future narrow literal-text projection/fallback?

Yes, later.

It is not required as the first fix for the tested issue.

### 6. Would adding it now duplicate information already available from Docling/Xberg?

For the immediate header/footer problem, mostly yes.

The first corrections should be:

- preserve Docling `FURNITURE`
- test Xberg with preservation-oriented content filtering

## Architectural Conclusion

The missing legal reference data is not primarily an engine-failure problem.

It is at least partly:

- `classification loss`
- `projection/export loss`
- `reading-order degradation`

This is good news.

It means Virgilio can likely recover important reference/header material by changing how existing extractor output is preserved and projected, without immediately adding a third extractor.

## Recommendation

Chosen recommendation from the prompt:

- **B — Fix/preserve existing projections and later add `pdftotext` as an independent literal-text projection**

Recommended next implementation direction:

1. Preserve Docling `BODY` and `FURNITURE` distinctly.
2. Do not silently merge furniture into canonical body Markdown.
3. Add a derived combined projection later where appropriate for search/reference recovery.
4. Test a narrow Xberg configuration change using `content_filter`.
5. Keep `pdftotext -layout` on the shortlist as a later literal-text projection, not as the immediate fix.
