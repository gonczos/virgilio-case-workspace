## Why this phase exists

The repository now has meaningful persisted PDF evidence and interpretation artifacts.

The evidence extraction boundary and heavy-processor execution policy have already been established.

However, the resulting persisted information remains awkward for a human to inspect. Understanding one PDF may still require direct SQL inspection or manually navigating representation/artifact directories.

This phase should provide a small human-friendly inspection surface over data that already exists.

The goal is:

```text
visibility over persisted evidence
```

not:

```text
new extraction
new interpretation
new processing
new semantic reasoning
```

## Objective

Expose already-persisted PDF evidence and interpretation outputs through a narrow, read-only inspection path.

For a selected PDF binary/document, a user should be able to understand at minimum:

* the original binary identity;
* basic persisted provenance/context already available;
* what interpretation representations are available;
* what PDF evidence representations/artifacts are available;
* which representation currently drives ordinary consultation;
* why that representation was selected;
* where evidence and interpretation outputs visibly differ.

The inspection path must operate over persisted repository data only.

It must not trigger extraction or processing.

## Core architectural boundary

Preserve the existing distinction:

```text
original PDF
    !=
evidence artifacts
    !=
interpretation representations
    !=
consultation selection policy
```

Do not flatten these into a synthetic extracted-document truth.

In particular:

* `pdf_literal_text` is evidence and is not equivalent to Docling/Xberg interpretation text;
* OCR text is not equivalent to native PDF text;
* signature structure is not equivalent to visible signature-appearance text;
* Docling and Xberg may legitimately disagree;
* the selected consultation representation is a policy result, not authoritative evidence;
* absence from one representation must not be presented as proof of absence from the original PDF.

The original binary remains the canonical evidence boundary.

## Read-only invariant

The inspection path must remain read-only over persisted repository/domain state.

An inspection request must not:

* enqueue a processing job;
* invoke a processor;
* trigger extraction;
* create a representation;
* replace a representation;
* create artifacts;
* mutate processing state;
* retry failed processing;
* change consultation selection;
* create or modify an explicit selection override;
* modify canonical/domain/importer records.

Ordinary HTTP/server logging or equivalent infrastructure-level observability is not considered domain mutation.

Workers must not be required for inspection.

## Required user-visible outcome

For a selected persisted PDF binary/document, expose a readable page or view containing at least the following.

### 1. Binary identity / provenance summary

Show useful existing persisted identity/context such as:

* `file_binary` identity;
* SHA-256;
* MIME/file type where available;
* document identity/context where naturally available through existing relationships;
* other small provenance fields already exposed by the current model where useful.

Do not build a new provenance model.

### 2. Original PDF access

Provide explicit access to the original PDF through the existing binary-serving path.

Do not expose local filesystem paths or raw storage URIs as the primary access mechanism.

Do not bypass the existing storage/binary-serving abstraction.

### 3. Available interpretation representations

Clearly identify interpretation representations such as:

* Docling;
* Xberg;
* human representation when one is already present in persisted representation data.

Expose useful representation identity/provenance fields where already available.

Do not fabricate a human representation when none exists.

### 4. Available PDF evidence

Clearly separate PDF evidence from interpretation.

At minimum inspect and expose persisted availability for:

* `pdf_literal_text`;
* `pdf_signature_metadata`;
* `pdf_structure_inventory`;
* `pdf_ocr_text` when present.

Do not imply that a missing persisted artifact proves that the underlying PDF lacks that kind of evidence.

Distinguish:

```text
artifact not produced / unavailable
```

from:

```text
evidence definitively absent from the source PDF
```

where the repository data supports that distinction.

### 5. Effective consultation selection

Show the currently effective ordinary consultation representation.

At minimum expose:

```text
selected representation: <id>
selection source: automatic policy | explicit override
```

Use the repository's existing effective-selection mechanism.

Do not implement a second selection algorithm for the inspection page.

Do not infer `automatic` versus `explicit override` merely from which representation wins.

Derive selection provenance from the existing persisted selection/override mechanism.

If there is no explicit override, do not imply that the automatically selected representation is authoritative truth.

### 6. Evidence/interpretation difference visibility

Provide enough visibility to make disagreement discoverable.

The inspection surface should make questions like these reasonably easy to investigate:

* Did literal PDF text preserve content that Docling/Xberg omitted?
* Does persisted PDF evidence report signature structures?
* Was OCR evidence produced?
* Does OCR contain text not visible in native literal extraction?
* Do Docling and Xberg materially differ?
* Which interpretation currently drives ordinary consultation?
