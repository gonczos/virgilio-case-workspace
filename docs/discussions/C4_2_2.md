Perform a narrow Phase C4 inspection/design pass for the Virgilio case workspace.

Do not implement the consultation UI yet.

Do not add React/Vite/MUI/PDF.js yet unless the repository already contains them and inspection requires understanding the existing setup.

Do not modify runtime behavior.

Do not modify database schema.

Do not create migrations.

Do not start Phase D search/indexing.

Do not add semantic enrichment.

The goal is to inspect the current repository and define the smallest practical implementation of:

```text
C4 — Corpus Consultation MVP
```

The accepted roadmap defines C4 as a deliberately thin human-facing consultation layer over the already completed canonical, processing, representation, comparison, selection, and BinaryStore infrastructure.

The intended MVP is:

```text
binary catalogue/grid
        ↓
binary detail
        ↓
original PDF + derived representation
        +
human-readable operational/provenance summary
```

Directus remains available as the raw/admin PostgreSQL consultation surface.

The custom UI should be the simple human-facing corpus experience.

# Objective 5 — Inspect binary/document context joins

The main C4 grid is binary-oriented, but humans need document context.

Determine how to efficiently obtain, for one `file_binary`:

```text
linked document(s)
document names/dates/types
bucket(s)
case_file(s)
case_workspace(s)
primary/non-primary document_binary relationship
```

Pay particular attention to the fact that:

```text
one file_binary
may link to multiple document rows
and/or multiple occurrences
```

Do not design the UI under an incorrect assumption that every binary maps to exactly one logical document.

Determine what a sensible human display label should be when:

* exactly one linked document exists;
* several linked documents share the same name;
* several linked documents have different names;
* metadata is sparse.

Do not change canonical identity rules.
