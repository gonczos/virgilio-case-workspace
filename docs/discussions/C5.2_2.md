## Identity strategy

Used the repository's existing immutable representation identity knobs instead of rewriting existing successful outputs.

- Docling:
  - old identity: profile `docling-default-v1`, version `2.123.1`
  - new identity: profile `docling-preserve-furniture-v2`, version `2.123.1-c5.2`
- Xberg:
  - old identity: profile `xberg-default-v1`, version `1.0.14`
  - new identity: profile `xberg-preserve-furniture-v2`, version `1.0.14-c5.2`

This produces new durable representations for the same binary while leaving historical artifacts untouched.

## Artifact decision

Chose Option A.

- `text.txt` keeps its existing body-oriented/plain-text semantics
- `complete-text.txt` is the new explicit complete-text artifact
- `markdown.md` remains the readable body-oriented Markdown projection
- `native.json` remains the native structured extractor artifact

This fits the repository better because current consultation `format=text` is segment-backed and existing successful representations already established `text.txt` as body-oriented text rather than as a universal completeness artifact.

Historical successful representations retain their original artifact semantics permanently.

## Processor behavior

### Docling

- readable text projection: `ContentLayer.BODY`
- readable Markdown projection: `ContentLayer.BODY`
- complete-text projection: `ContentLayer.BODY + ContentLayer.FURNITURE`

### Xberg

Configured explicitly with preservation-oriented filtering:

- `include_headers=True`
- `include_footers=True`
- `strip_repeating_text=False`
- `include_watermarks=False`

Current Xberg C5.2 writes both `text.txt` and `complete-text.txt` with the same preserved text because Xberg does not expose the same BODY/FURNITURE distinction used by Docling.

## Real-document validation

Validated on three known problematic PDFs already present in the local corpus:

- `6836f8732aae33a3bc79491748134bd2a77a7b48aeaa2cd7c66647ff1f468f1c`
- `17eb40fa6ca2c37156d9c230640ff03efbddfa531111f09bb03a7152f9e4a691`
- `24c8c65472964ea3dcb0b279e0a3cc1df3a56b78382abb345d863e3630a8b368`

Representative finding:

- older Docling body-oriented text for `6836...` omitted or de-emphasized header/footer reference material such as `Juízo de Família e Menores de Sintra - Juiz 6`
- new Docling `complete-text.txt` preserved that header/footer material explicitly
- new Xberg C5.2 output also preserved the same reference strings under the new explicit filter policy
