# Objective 1 — Inspect the actual timeout mechanism

Before changing any value, identify exactly where the current:

```text

```

timeout originates.

Determine whether it is:

* global worker timeout;
* processor-specific timeout;
* child-process timeout;
* subprocess wrapper timeout;
* extraction adapter timeout;
* rollout-script timeout;
* some combination.

Inspect all relevant code paths.

For each processor, determine what happens when the timeout expires:

```text
docling
xberg
pdf_literal_text
pdf_signature_metadata
pdf_structure_inventory
pdf_ocr_text
```

Answer:

1. Which layer owns the timeout?
2. Is the child process actually terminated?
3. Are child processes/process trees reliably cleaned up?
4. Can a timed-out extractor continue running after the processing job is marked failed?
5. Is timeout failure persisted with a distinguishable error code?
6. Is elapsed duration retained?
7. Is the timeout currently configurable per processor?
8. Is it configurable per invocation/job?
9. Does changing one timeout inadvertently change every processor?

Do not change timeout values until this is understood.

# Objective 2 — Inspect concurrency mechanics

Determine the current concurrency model.

Specifically inspect:

* number of processing workers;
* whether one worker processes one job at a time;
* whether rollout tooling starts several workers;
* whether processors have independent concurrency limits;
* whether Docling and OCR can execute concurrently;
* whether multiple Docling jobs can execute concurrently;
* whether multiple OCR jobs can execute concurrently;
* whether cheap evidence jobs compete for the same worker capacity as expensive jobs.

Determine whether the observed timeout failures may have been influenced by concurrent CPU/RAM pressure.

Do not assume the failure means merely:

```text

```

It may instead mean:

```text
15 minutes under current concurrency/resource contention is too short
```

Report the actual current behavior.

If the evidence points primarily to contention rather than a globally
insufficient timeout, prefer reducing heavy concurrency or separating
heavy execution classes over simply increasing every timeout.
