# C5.3.9 Result — Portable Export Inspection/Verification

## Outcome

C5.3.9 added a package-side reader/verifier for the committed C5.3.8 portable
export contract plus a DB-independent admin CLI inspection command:

```text
node app/processing-admin.mjs inspect-export --package <dir>
```

The inspection path operates only on the exported package directory.

It does not open a DB connection, assert processing schema availability,
materialize through `BinaryStore`, or invoke processor implementations.

## Reader/verifier contract

The implementation validates:

- `manifest.json` presence and parseability;
- `package_format = "virgilio-portable-evidence"`;
- `package_version = 1`;
- package-local path safety for:
  - `original_binary.package_path`;
  - `representation_artifacts[*].package_dir`;
  - `representation_artifacts[*].copied_files[*].relativePath`;
- original-binary byte size;
- original-binary SHA-256;
- existence of every manifest-listed copied artifact file;
- consistency between persisted representation `artifact_rel_path` metadata and
  `manifest.package_contents.representation_artifacts`.

The inspector explicitly preserves the C5.3.8 semantic distinction:

- persisted `artifact_rel_path` remains provenance/debug metadata about the
  source representation artifact location inside Virgilio;
- package-local `package_dir` and `copied_files[*].relativePath` identify the
  exported copy inside the portable package.

## DB-independent CLI dispatch

`app/processing-admin.mjs` now dispatches `inspect-export` before the existing
DB/bootstrap path.

All DB-dependent commands continue to run through the prior
`withClient(...)` + `assertProcessingSchema(...)` flow.

No broader CLI framework or unrelated command refactor was introduced.

## Integrity and failure checks

The inspector rejects at least:

- missing or malformed manifest;
- unsupported package format/version;
- absolute or package-escaping package-local paths;
- missing original binary;
- original size mismatch/truncation;
- original SHA mismatch;
- missing manifest-listed artifact file;
- artifact-entry inconsistencies for persisted representations.

The path checks run before existence or integrity verification.

## What remains unverifiable by design

The inspector verifies only what the C5.3.8 package contract actually exports.

It does not attempt to:

- consult the live database;
- reconstruct or verify source-storage absolute paths;
- re-resolve persisted `artifact_rel_path` against the local workspace;
- prove anything about artifacts or provenance not copied into the package;
- add new hash/integrity guarantees for artifact files beyond existence and
  manifest consistency.
