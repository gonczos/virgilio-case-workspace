## Runtime boundaries used

Structured read models come only from the committed C4.1 API:

- `GET /api/consultation/binaries`
- `GET /api/consultation/binaries/:sha256`
- `GET /api/consultation/representations/:id/content?...`

Original binary preview continues to use:

- `GET /binary/:sha256`

The UI does not query PostgreSQL or Directus directly.

## UI behavior

`/binaries`

- shows a paged catalogue table over the binary read model
- uses backend `display_name`
- shows file type, size, linked document/case counts, compact processing status, effective representation, and review state
- row click navigates by SHA-256 to the detail page

`/binaries/:sha256`

- header shows display name, file type, size, shortened SHA, linked counts, review state, and effective representation
- left pane shows the original PDF via PDF.js when the binary is a PDF
- non-PDF binaries fall back to a simple no-preview panel with an original-file link
- right pane shows the selected representation and chosen format
- lower panels show context, processing, quality/comparison, provenance, and collapsed technical details

## Effective versus viewed representation

The representation selector controls only the representation being viewed.

It does not mutate:

- effective representation
- explicit selection
- preferred/default representation
- processing state

The detail page initializes the viewed representation from the backend-provided effective representation when one exists, otherwise from the first available representation.

Format selection is view-only and prefers:

- `markdown`
- then `text`
- then `native-json`
- then the first available format

## Representation viewers

- `text` renders in a scrollable pre-wrapped panel
- `markdown` renders safely with a rendered/raw toggle
- `native-json` renders as formatted JSON

Unavailable formats stay unavailable. For example, the current Xberg sample does not advertise Markdown, and the UI does not offer it.

## PDF viewer behavior

The PDF panel remains intentionally basic:

- current page render
- previous/next navigation
- page count chip
- zoom in/out

No text layer, search, annotations, synchronization, or range-request work was added in this slice.

## Technical-details guard

The technical-details panel is collapsed by default and stays presentation-only.

It exposes safe IDs and raw JSON-oriented details already returned by the API, but does not display local artifact filesystem paths.
