# Accepted runtime boundaries

Use the existing backend contracts.

Structured consultation API:

```text
GET /health

GET /api/consultation/binaries

GET /api/consultation/binaries/:sha256

GET /api/consultation/representations/:id/content?format=text
GET /api/consultation/representations/:id/content?format=markdown
GET /api/consultation/representations/:id/content?format=native-json
```

Original binary:

```text
GET /binary/:sha256
```

The UI must consume these boundaries rather than querying PostgreSQL or Directus directly.

Architecture:

```text
React UI
   ↓
consultation API
   ├── canonical/context aggregation
   ├── processing state
   ├── representation selection
   ├── comparison / attention
   └── representation content

original PDF
   ↓
file-gateway
   ↓
BinaryStore
```

Directus remains the raw/admin surface.

---

# C4.2 objective

Implement only:

```text
/binaries

/binaries/:sha256
```

The experience should make the existing corpus visibly useful.

A human should be able to:

1. browse binaries;
2. understand what each binary is connected to;
3. see whether it has been processed;
4. see the effective representation;
5. identify review-needed items;
6. open a binary;
7. view the original PDF;
8. switch between available representation outputs;
9. inspect processing/provenance/comparison information.

The UI is consultation-only.

# Representation selector

The right pane needs two distinct selections:

```text
representation
format
```

Example:

```text
Representation: Docling
Format: Markdown
```

Available choices must come from:

```text
representations.items
available_formats
```

Do not hard-code:

```text
Docling = markdown
Xberg = text
```

except for human-friendly labels.

The backend is authoritative about format availability.

---

# Critical selection rule

The representation selector changes only what the user is VIEWING.

It must not change:

* effective representation
* explicit selection
* preferred representation
* processing state

Do not call a mutation endpoint.

Do not visually label the selector as:

```text
Preferred representation
```

or:

```text
Select representation
```

Use language such as:

```text
View representation
Representation
```

The UI should separately indicate which representation is currently effective.

For example:

```text
Effective
```

badge beside the effective representation.

Viewing Xberg while Docling is effective must remain completely valid.

---

# Initial representation shown

When the detail page loads:

prefer the backend-provided effective representation.

If no effective representation exists:

* choose the first available representation for viewing;
* or show a clear "No representation available" state.

This is a UI viewing fallback only.

Do not modify backend selection.
