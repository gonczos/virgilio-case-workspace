The fixture-scoped ingestion defined in architecture commit `553f32d` was implemented against the frozen expansion and foundation evaluation artifacts. It persists exactly 111 reviewed positive extractor observations. The 50 negative controls and three ambiguous diagnostics remain validation inputs and are not persisted.

The ingester validates frozen evaluation counts, representation hashes, raw spans, label spans, and lossless mapping from representation coordinates to one stored segment before planning writes. Observation keys use `reference-text-observation-identity-v1`; metadata retains representation and segment coordinates, content hashes, rule key, family, parsed candidates, and exact label provenance. Targets, namespaces, document identities, binary identities, and relationships remain unresolved.

The initial dry run planned 111 inserts without mutations. Transactional write committed 111 inserts. The immediate repeat reported 111 unchanged observations, zero lifecycle mutations, and `mutation_statements_issued: false`. Direct database verification found 111 canonical current observations, zero target candidates, zero ingestion review states, and zero human-review rows.

The legacy pilot seeder now reuses a matching canonical v5 identity and skips unmatched legacy-key v5 insertions. During validation before that guard was added, one pilot-seeder run created 67 current legacy-key v5 rows outside the frozen scope. A bounded corrective pass authenticated every row through its historical key, pilot fixture metadata, and recorded creation evidence, then transitioned all 67 to `retired_source_absent` with immutable `retire_out_of_frozen_scope` events and corrective provenance. No row was deleted or rewritten. The resulting state is exactly 111 canonical current rows and 67 retained historical rows. Subsequent seeder and ingestion reruns added no rows and changed no lifecycle events.

Focused validation covers deterministic identity, unchanged reruns, reactivation, exact-span supersession, authenticated legacy reconciliation, ambiguous legacy rejection, retirement boundaries, pilot-seeder compatibility, and rollback after a forced mutation failure. A live transaction test creates a reviewed older observation, supersedes it, verifies byte-for-field review preservation and the replacement link, proves exactly one current observation, and rolls back its observation, review, and lifecycle-event rows. The legacy seeder integration test also runs inside a caller-owned transaction, compares full v5 observation/review/lifecycle snapshots, and rolls back those rows. These state-affecting tests advance PostgreSQL sequences when they allocate identities. Earlier validation runs executed the legacy seeder with its normal committed transaction and consequently refreshed `updated_at` on existing pilot-owned non-v5 rows through its established upsert behavior. Those historical timestamps were not rewritten to simulate their earlier values.

Saved durable consultation samples are filtered to `reference-text-observation-identity-v1` and the exact `frozen-v5-expansion-and-foundation` fixture scope. They cover direct attachment, physical folio with procedural contexts, both explicit register forms, the inherited damaged French label, and a coordinated procedural reference. Correction history is not mixed into these canonical samples. Because the live database has no durable reviewed historical segment observation, the older-procedural and current-versus-retained-reviewed-history cases are captured through a clearly labelled `transactionally_constructed_and_rolled_back_validation` sample: a real older observation and review are inserted at a real canonical source span, superseded by the actual ingester, read through the consultation lookup and serializer, saved, and then rolled back. No sample observation row, review row, or lifecycle-event row persists. This generator is explicitly state-affecting validation rather than a side-effect-free routine: PostgreSQL sequence allocation is nontransactional, so the observation and lifecycle-event sequences advance even though their rows roll back. Sequence values are observed in future generated artifacts and are never restored with `setval`. The retained response artifact was produced before sequence values were captured and records that limitation rather than inventing unavailable values.

No UI, graph, AI, target resolution, corpus-wide extraction, schema, or normalization change is included.
